## Keep an implementation near the operation that needs it

An operation sometimes needs a small implementation useful only there—for example, a Message that combines the operation's prefix with its owning object's name. Giving that helper a broad top-level role can obscure why it exists. Local and anonymous classes let its definition stay beside the operation that creates it.

A **member class** is declared in another type's body. A **local class** is declared within a block, such as a method body, and has a name available in that scope. An **anonymous class** is declared inside a new expression without its own source name. Both create ordinary objects with identity, fields and instance methods; an interface can expose the result without exposing the helper's local name.

Such an implementation can **capture** a surrounding local value: retain access to its value after the creating call returns. Captured locals must obey the final/effectively-final rule explained below. The source compares a named local implementation with an unnamed implementation, then distinguishes their own this from the enclosing object's this. No lambda syntax is needed.

## Read the anonymous class expression

`new Message() { ... }` creates an instance of an unnamed class implementing Message. It does not construct the interface itself. The braces contain that class's fields and methods; the final semicolon ends the return statement. When the named type is a class instead, the anonymous class extends it and constructor arguments go in the parentheses. An anonymous class cannot declare an ordinary named constructor; an instance initializer can perform additional initialization.

The anonymous object's `this.name` is inner. `LocalAnonymousLesson.this.name` belongs to the enclosing object and is Ada. Those are two receivers and two fields, not two names for one field. In a static method there is no enclosing instance to obtain with Outer.this. A static nested class is nested but is **not** an inner class: it has no automatically associated enclosing instance.

## Capture values under an effectively final rule

Prefix is a parameter read by both implementations. A captured local/parameter must be final or effectively final: it is not reassigned after initialization. Removing the written final alone is allowed if no assignment changes it. Adding `prefix = prefix.trim()` would make these captures illegal; compute a separate final cleaned variable first.

This restriction protects the captured **variable's binding**, not every reachable object. A captured final array reference can still identify writable components. Such mutation creates ordinary aliasing and, if shared across threads, coordination obligations. It is not a pass-by-reference exception to Java's argument rules. Retaining an inner object can also retain its enclosing object, which matters when the inner implementation outlives a large owner. [JLS inner classes and capture](https://docs.oracle.com/javase/specs/jls/se25/html/jls-8.html#jls-8.1.3), [JLS anonymous classes](https://docs.oracle.com/javase/specs/jls/se25/html/jls-15.html#jls-15.9.5)

## Practice: choose a named member, local or anonymous type

<details>
<summary>The implementation grows several operations and needs reuse in three methods. Keep it anonymous?</summary>

A named member or top-level class gives the implementation a discoverable name and one place to maintain its behavior. Use a local class when naming helps within one operation; use an anonymous class for a small one-off implementation. The choice changes organization, not whether the created instance is an ordinary object with identity and method calls.

</details>

<details>
<summary>Can a returned Message keep reading prefix after the factory method returns?</summary>

Yes. The example does exactly that. The captured value remains available to the object. This does not preserve the factory invocation's active frame or allow later reassignment of its local variable to redirect the captured binding.

</details>
