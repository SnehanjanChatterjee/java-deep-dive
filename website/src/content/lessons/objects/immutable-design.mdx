## Keep the published value stable

An **immutable value** has the same observable meaning throughout its lifetime after construction. A route created with stops two and four should still report those stops later, even if the caller edits an array it used to build the route. Stable values simplify reasoning about equality, sharing and stored results because a reader cannot silently change another reader's value.

The challenge is **alias control**. Final fields prevent reassignment of those fields, but a final array reference still identifies writable components. A caller may keep the input array or receive an internal array through an **accessor**, a method exposing stored information. Either path could allow an external write to change the route.

A **defensive copy** detaches mutable state at such a boundary. Copy on input to prevent the original caller's later edits, and copy on output to prevent an accessor caller's edits. This is an ownership policy, independent of whether two route objects compare equal. Trace the two boundaries separately in the example.

Construction clones the supplied primitive array. Changing input[0] afterward affects only the caller's array. Stops() clones again, so changing an accessor result also leaves the route unchanged. The final printed component is still 2. An independently constructed route with components 2 and 4 compares equal.

## Explain every ownership decision

The class is final, fields are private/final and there is no **mutator**, an operation for changing its stored value. The input null check declares that a route always owns an array. Empty routes are permitted. Input cloning establishes independent primitive components, and output cloning avoids leaking them. Equals uses Arrays.equals and hashCode uses Arrays.hashCode; ordinary array identity would not express route-value equality.

<Diagram client:visible definition={"flowchart LR\n I[Caller input array] -->|copy| V[Private array]\n V -->|copy| O[Caller output array]\n I -. mutation stays here .-> I\n O -. mutation stays here .-> O"} caption="Two boundary copies protect the stored value from both incoming and outgoing aliases." />

Each copy costs O(n) time and storage. Equals takes O(n) worst-case comparisons; hashing reads all n values. Do not advertise an accessor that copies an array as constant-cost. For nested mutable objects, a structural container copy may be insufficient; each element needs a policy, as the preceding matrix example showed.

## Prove stability from every available mutation path

List the constructor inputs, stored fields, exposed accessors, subclass hooks and mutable collaborators. The route closes its input path by copying, its output path by copying, and its subclass path by being final. The primitive elements need no further object copy. A route containing mutable Stop objects would need a per-Stop policy as well; marking only the array field final would leave those objects writable.

Final is one way to control subclass behavior, not a logical prerequisite for every immutable design. A non-final type can carefully restrict construction and overridable observations, but the proof becomes harder because subclasses can expose changing state or alter equality. Prefer the simpler final value class when extension is not a requirement. Do not claim final universally provides a performance gain or turns a referenced graph immutable.

<details>
<summary>Is returning a fresh copy wasteful if the caller only reads it?</summary>

It has an O(n) cost, but is required by this array-returning API's ownership promise. Changing the API to indexed read operations can avoid exposing a mutable array and avoid copying on every read; it also changes client ergonomics. Choose deliberately rather than deleting a defensive copy while keeping the same stability claim. Equality and hash computation also have costs, even for an immutable value.

</details>

## Avoid overpromising deep immutability

An unmodifiable view prevents writes through that view but can continue observing mutations through other aliases. A snapshot detaches container structure; mutable elements may still be shared. A copy constructor is ordinary code, not an automatic deep-copy guarantee. A retained mutable comparator or buffer can also invalidate a supposedly stable object.

Avoid overridable normalization during construction. A cached hash is safe only while its represented equivalence relation stays stable and any sharing/publication requirements hold. Immutability simplifies concurrent use but does not justify leaking this during construction.

## Keep one shared instance only when the domain needs one

A singleton-style API restricts ordinary construction and returns a class-wide shared instance. It solves an identity/ownership requirement, not immutability by itself. The eager form uses concepts already taught: a private constructor, a private static final field and a public static accessor. This source excerpt comes from ObjectOperationsLesson, whose full copy/clone demonstration appears after exceptions:

```java
private static final ObjectOperationsLesson INSTANCE = new ObjectOperationsLesson();
private ObjectOperationsLesson() { }
public static ObjectOperationsLesson instance() { return INSTANCE; }
```

Class initialization establishes INSTANCE before the ordinary instance accessor use. Calls return copies of the same reference; the matching runnable demonstration compares two results as true. The class is final, so ordinary subclassing cannot introduce another construction path. The claim is about this runtime class and its ordinary API, not one universal object across separate JVM processes or distinct defining class loaders.

If the shared instance exposes mutable state, that state needs the same invariants and concurrency policy as any other shared object. Do not replace dependencies with global singletons solely to avoid constructor parameters: tests and clients may need independently configured instances. Lazy initialization, concurrent publication, reflection and serialization boundaries require additional contracts; eager construction here avoids introducing unlearned double-checked locking as an introductory pattern.

## Practice: remove one copy and predict the failure

What breaks if the constructor stores stops directly? What breaks if stops() returns the field directly?

<details>
<summary>Answer</summary>

Without the input copy, the original caller can mutate the stored route after construction. Without the output copy, any accessor caller can mutate it. Keeping only one copy protects only one boundary. A zero-length input still needs a defined policy, although it has no mutable components to overwrite. The generics module later extends this design to a list of mutable Date elements and immutable modern time alternatives.

</details>
