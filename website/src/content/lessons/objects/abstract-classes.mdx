## Share an invariant without pretending every base is complete

Two related classes may perform the same overall operation while differing in one step. An **abstract class** can declare that shared operation and state without pretending to provide a complete instance by itself. It cannot be instantiated directly; a **concrete subclass** completes the required behavior and is the class actually constructed.

An **abstract method** declares a required signature without a body. An implemented method has a body and can call such a required operation on the completed object's receiver. An abstract class can also have fields, constructors, static members and fully implemented methods. The abstraction marks an incomplete type for construction, not a ban on shared implementation.

Here every Form has a non-null label and the same `label:content` formatting algorithm. TextForm stores text; CountForm stores a nonnegative number. The base owns the shared label and algorithm, while each concrete class supplies its content representation. The varying content operation is sometimes called a **hook**: one explicit extension point within the shared algorithm.

## Follow construction before invoking the varying step

New TextForm invokes its constructor, which calls super(label). Form's constructor checks and stores the label. Control then returns to TextForm's constructor to check/store text. No content call occurs during that construction. After the new expression completes, main stores the reference as Form and invokes format.

Format is implemented once in Form. It reads the base's private label, invokes content on the current receiver and joins the results. For the TextForm receiver, virtual dispatch reaches TextForm.content; for CountForm it reaches CountForm.content. The inherited algorithm is the same even though the stored representation of content differs.

The abstract method's contract must make the shared algorithm valid. This example's two implementations return non-null text. An unrelated subclass returning null would produce the literal text null during concatenation; the base declaration alone cannot prove every domain promise. Decide whether the base should enforce a result constraint or whether all implementations must satisfy it, and test that policy.

## Read abstract, final and protected together

Form is abstract because an ordinary Form has no completed content behavior. Content is abstract and protected, exposing the implementation obligation to subclasses without making it the caller's main operation. Format is final so subclasses cannot replace the shared formatting algorithm; they vary only its designated hook. Private label remains controlled by Form even when it is part of a subclass instance.

An abstract class may have no abstract methods when its designer still wants to prohibit direct construction. Conversely, a class declaring an abstract method must be abstract. A concrete subclass must complete all inherited abstract obligations or itself remain abstract. Constructors are not abstract: their job is to initialize each actual subclass object, and they are not inherited methods to override.

Making a class abstract does not protect a constructor from unsafe virtual calls. If Form's constructor called content, it could dispatch before TextForm.text or CountForm.count had been initialized by their constructors. The example deliberately calls the varying step only after construction is complete. [JLS abstract classes and methods](https://docs.oracle.com/javase/specs/jls/se25/html/jls-8.html#jls-8.1.1.1)

## Choose an abstract base, interface or collaborator

Use an abstract base when closely related implementations should share per-instance state and a common algorithm under one inheritance boundary. Use an interface when clients need a capability that can be implemented by unrelated classes without sharing that representation. A class can extend only one class, so choosing this base uses that inheritance slot.

Composition can express the varying content as a supplied collaborator instead. That supports changing or testing the collaborator independently and avoids inheriting a base's unrelated operations. An abstract base is not a “partial percentage” of abstraction, and an interface is not a guarantee that implementation details never appear in default methods. Choose the contract and invariant that fit the client.

<summary>Add EmptyForm that renders no content. Which methods and constructor work are required?</summary>

```java
static final class EmptyForm extends Form {
    EmptyForm(final String label) { super(label); }
    @Override protected String content() { return ""; }
}
```

It initializes the inherited required label and supplies the abstract content step. It inherits format, so `new EmptyForm("note").format()` gives `note:`. It must not override final format. No duplicate label field or string-joining algorithm is needed. Null label follows the common constructor rejection rather than inventing a subtype-specific fallback.
