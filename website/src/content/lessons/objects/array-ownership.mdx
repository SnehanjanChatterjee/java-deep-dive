## Trace a two-dimensional array as an object graph

A nested array is easiest to understand as an **object graph**: objects are the nodes, and references are the connections between them. An int[][] has an outer array whose components identify int[] row arrays. Rows are separate objects and can be shared, null or different lengths; a two-dimensional declaration is not a promise of one rectangular block.

A **shallow copy** creates a new container and copies its component values. For int[] those are primitive ints, so they become independent components. For int[][] the component values are row references, so copying them leaves the same row objects shared. A **deep-copy policy** decides which referenced objects to detach as well. The required depth depends on the promised ownership boundary.

The final branch also demonstrates **array covariance**: a more specific reference array can be viewed through a broader array type while retaining its actual component-type check. ## Choose a deep-copy policy for this shape

For an independent primitive matrix, copy the outer array **and every non-null row**. A valid policy can preserve null rows and ragged lengths. For arbitrary object graphs, a recursive copier additionally needs to decide how to preserve shared references and cycles; blindly recursing is not a universal deep-copy algorithm.

```java
static int[][] copyRows(final int[][] source) {
    final int[][] result = source.clone();
    for (int row = 0; row < result.length; row++) {
        if (result[row] != null) {
            result[row] = result[row].clone();
        }
    }
    return result;
}
```

This rejects a null outer input through the clone call. With r rows and n total primitive components it takes O(r+n) time and space. Returning an internal mutable row still leaks ownership even if the accessor returns a copied outer array.

## An array retains its runtime component type

Reference arrays are covariant: a String[] can be assigned to Object[]. The variable's declared type then permits a source-level Object store, but the actual array remains a String[]. Storing an Integer violates its runtime component type, producing ArrayStoreException. The cast/assignment does not convert the array or its existing elements.

The String array was initially filled with a valid String. Storing another String through the broader Object[] reference would also be valid; storing an Integer is what violates the actual component type. Widening the reference changes the source view, not the created array's identity or permitted stored values.

## Separate runtime type, content equality and copying

Every array is an Object, including int[]. But int[] is not Object[]: its components are primitive ints, not object references. An int[][] is an Object[] because its components are int[] references. Covariance changes which array references can be assigned; it does not box individual primitive components or change the actual component type of an existing array.

Ordinary array equals compares identity; Arrays.equals compares one-dimensional contents, and Arrays.deepEquals can compare nested array contents. None copies those arrays or prevents later mutation. Conversely, cloning an outer array changes its identity without changing the row identities. State the operation's purpose before choosing a method with deep in its name. Here copyRows preserves null rows and copies every non-null primitive row, matching the complete source and its null/ragged-row tests. A different domain might reject missing rows, but that would require a different validation policy.

<details>
<summary>Two source entries identify the same row. Does copying each row independently preserve that alias relationship?</summary>

No. It produces two independent row copies with equal contents. That is appropriate when each result row must be independently owned, but differs from a graph-preserving copy. Arbitrary reference graphs can contain shared nodes and cycles; copying such a graph requires an identity-tracking policy. A specialized primitive-matrix copy should not be advertised as a universal object-graph cloner.

## Practice: identify the protected boundary

Does returning `internal.clone()` protect a stored int[][] matrix from caller writes?

<details>
<summary>Answer</summary>

Only the outer array is protected. The caller can still change shared rows. CopyRows supplies detached primitive rows under its declared null/ragged-row policy; call it at input and output boundaries if a class promises snapshot ownership. Generic collections use different compile-time type rules, explained after type parameters; this chapter needs no generic-varargs assumptions.

</details>
