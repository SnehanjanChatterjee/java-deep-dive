## Give related state and behavior one boundary

Suppose two players need separate scores and the same operations for awarding/reading points. Keeping unrelated variables and helper methods for each player would duplicate both names and rules. **Object-oriented programming** organizes related data and operations around objects, so each player's state can be managed through one common definition.

A **class** declares such a type. A **field** stores part of its state; a **method** defines an operation. **State** means the values currently stored, and **behavior** means the operations the type exposes. An **object**, or **instance**, is one created value of that class with its own instance fields. Two ScoreCards follow one class definition while holding different point totals, just as two paper cards can share a layout and contain different marks.

A variable of class type holds a **reference** identifying an object. A call such as `first.awardPoint()` identifies the object receiving the operation; first is the **receiver**. Start by distinguishing the class declaration, each new object and each variable referring to an object. The program then makes the difference visible by changing only one card.

<JavaExample file="ScoreCard.java" output={"2\n0\nfalse"} />

`new ScoreCard()` creates and initializes a new object, returning a reference to it. Declaring `ScoreCard first;` alone creates a variable, not a ScoreCard. The variable must receive a reference before use. `first` and `second` refer to different objects, so their identity comparison is false.

## Read the declaration as state plus operations

`private int points;` declares an instance field. Every ScoreCard gets its own points, automatically initialized to zero. Private means callers use the published methods rather than directly writing the field. Unlike a field, a local variable inside main must be assigned before it is read.

`awardPoint()` is an instance method. In `first.awardPoint()`, first supplies the receiving object. The unqualified field name points inside the method means the field on that receiver. Two calls increase only the first card's value. `second.points()` returns zero because no award was made to the second object.

The field points and the method points() have different roles: one stores state, the other publishes a read operation. Parentheses mark an invocation. A method can return a primitive, return an object reference or perform an action and return void. A class with no declared constructor receives a compiler-provided default constructor; the next chapter replaces it with explicit initialization rules.

## Class members do not need an object receiver

Fields and methods are **members** of a class. Main is static: it belongs to ScoreCard as a class. A static method has no implicit current ScoreCard, so it cannot read points without identifying an object. The expression `first.points()` provides that receiver. Instance methods instead have an implicit current object, called this.

## Trace a receiver instead of reading the class like a script

The class body declares members; Java does not execute every method simply because it appears in the file. The launcher calls main, and main's statements create objects and call selected methods. Inside awardPoint, `points++` means `this.points++`: the call supplies the receiver. One method declaration can therefore operate on many independent cards without duplicating the method's source for each object.

Use this three-step trace when predicting state: identify the object created by each new expression, connect reference assignments to those objects, then apply each instance call to its receiver. A null reference identifies no object; calling `missing.awardPoint()` fails before that instance method can operate on a card. A local variable named points would shadow the field, so use this.points when both names occur.

<details>
<summary>Does declaring ScoreCard third create a third card? Does calling points() award one?</summary>

Neither. A declaration introduces a variable; it must later receive a reference before a read. A read operation returns the current stored number; only awardPoint mutates that number in this class. Separating queries from state changes makes both the API and its trace easier to reason about. The example's card intentionally uses ordinary int increment; a domain counter that must reject overflow needs an explicit policy, as the next constructor lesson supplies.

</details>

## Practice: draw two objects and one alias

After `ScoreCard alias = first; alias.awardPoint();`, what does first.points() return? What does second.points() return?

<details>
<summary>Answer</summary>

They return 3 and 0. Assignment copies the reference; it does not copy the object. Alias identifies the existing first card, so its method changes that object's field. There are still two ScoreCard objects, not three. The references chapter develops this graph and distinguishes mutation from reassignment in method calls.

</details>
