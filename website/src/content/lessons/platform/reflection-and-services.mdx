## Intercept calls through an interface boundary

A dynamic proxy is a runtime object implementing selected interfaces. Calls on that object are routed to an InvocationHandler receiving the proxy, a Method describing the call and its arguments. It can add behavior and delegate to an existing target. It is not a transparent subclass of any arbitrary concrete class.

## Give Object methods a consistent policy

If equals blindly delegated to target, proxy.equals(proxy) would become target.equals(proxy), normally false for identity-based target equality. The example instead gives every proxy its own identity: it equals itself and not its target. HashCode uses the proxy's identity hash, and toString returns fixed diagnostic text without recursively invoking the proxy.

Identity hashes may collide: distinct proxies need not have different numerical hash codes. If an API wants proxy/target domain equality, it must design a symmetric, matching equality/hash policy on both sides. It cannot infer that policy from the existence of a target field.

## Preserve the service's failure contract

Method.invoke wraps a target exception in InvocationTargetException. The handler unwraps and throws its cause. The interface declares IOException, so the empty-name target failure reaches its caller as that original checked category. An undeclared checked failure thrown by a handler is instead exposed through UndeclaredThrowableException. That wrapper is different from the target's own declared contract.

Arguments for a zero-argument method may be null. Primitive arguments/results are boxed at this boundary, and an incompatible result can fail conversion; returning null for an int result is not a valid zero. Handle the advertised interface shape rather than assuming every intercepted method looks like greet.

## Define defaults, metadata and self-invocation

This Greeting has no default method. If an interface adds one, choose whether to call its default implementation or another target policy. InvocationHandler.invokeDefault is available on Java 16+ for eligible defaults; ordinary reflection on the proxy is not a general recursion-free default invocation strategy.

Annotations on an implementation may differ from those on the interface Method received by the handler. Self-invocation within the target does not return through the outer proxy automatically. The class loader must see the selected interfaces, and module/access restrictions still participate in proxy construction and invocation.

## Practice: explain a recursive diagnostic

Why can `return "proxy=" + proxy;` in the toString handler fail? How should a target IOException be reported?

<details>
<summary>Answer</summary>

Concatenation asks for proxy.toString, re-entering the same handler and repeating the call. Use nonrecursive diagnostic data, such as a fixed label or target.getClass().getName. For IOException, preserve the original cause from InvocationTargetException so a caller compiled against Greeting sees its declared failure contract. Handle Object methods before ordinary delegation, and test reflexivity, null/target/other-proxy inequality, stable hashing and target failure identity.

</details>
