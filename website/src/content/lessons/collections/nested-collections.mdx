## A list of lists stores row references

A List of List of Integer is not a rectangular block of integer storage. The outer list stores references to row lists, and each row owns its own size and storage. Rows can have different lengths, be shared by several positions, or be absent until constructed. Generics describe the nested element type, not the dimensions.

For a small seating grid, construct the row objects as well as the outer container. A capacity argument alone creates neither rows nor cells:

```java
final List<List<Integer>> grid = new ArrayList<>();
final List<Integer> first = new ArrayList<>(Arrays.asList(0, 0, 0));
final List<Integer> second = new ArrayList<>(Arrays.asList(0, 0, 0));
grid.add(first);
grid.add(second);
grid.get(0).set(1, 17);  // [[0,17,0], [0,0,0]]
grid.get(1).add(9);      // [[0,17,0], [0,0,0,9]]
```

Read `List<List<Integer>>` from outside inward: an ordered list whose elements are row-list references; each row holds Integer references. The two new row objects are independent even though their initial contents are equal. The complete program generalizes construction into matrix, then compares copy strategies and deliberate shared-row behavior.

The complete file contains matrix and copyRows for this row exercise. Its freezeDistinctRows helper is an optional application after the Sets group, explained in the later set-of-sets section; it is not needed to construct or copy the grid.

## Create a row before replacing one of its cells

`grid.get(0).set(1,17)` means: get the first row object, then replace that row's existing cell one. Neither get nor set creates a missing row/cell. Constructing an outer ArrayList with capacity two still leaves outer size zero.

| Expression | Effect |
| --- | --- |
| outer.add(new ArrayList&lt;&gt;()) | Creates one row position referencing an empty row |
| outer.get(0).add(17) | Appends the first cell to that row |
| outer.get(0).set(0,18) | Replaces the existing first cell |
| outer.get(0).add(0,19) | Inserts a cell and shifts the row suffix |
| outer.add(0,newRow) | Inserts a row and shifts outer row positions |

In the complete program, replacing row zero's second cell gives [0,17,0]. Appending 9 to row one makes it [0,0,0,9]. The grid is now jagged. A loop must use each current row's size rather than assuming all rows equal row zero.

A primitive int[][] has different component/storage rules, but also stores row-array references at its outer level. The array-ownership chapter explains that related alias model. A List&lt;List&lt;Integer&gt;> is also not assignable from List&lt;ArrayList&lt;Integer&gt;> merely because ArrayList implements List; generic parameterizations are invariant. The copyRows parameter deliberately uses an extends wildcard for its outer reader.

## Copy the outer list, copy rows, or copy elements?

An outer-only new ArrayList&lt;&gt;(grid) creates a new list of the same row references. After setting grid[0][0] to five through the row API, both outer lists observe [5,17,0]. copyRows instead constructs a new list for each row and retains the earlier [0,17,0].

Integer elements are immutable in this example." />

Per-row copying costs O(number of rows + total cells), including jagged rows. It shares Integer elements safely because those values are immutable. With mutable element objects, copying rows alone would still share them. A correct deep snapshot must state exactly which mutable levels are detached.

## Diagnose a repeated-row alias

Collections.nCopies(2,sharedRow) repeats the same reference twice. Wrapping the result in new ArrayList makes the outer structure mutable but does not produce new row objects. Changing aliases.get(0).set(0,8) therefore changes the row seen at both positions: [[8,0],[8,0]].

A useful identity check is `grid.get(0) == grid.get(1)`. It should be false when the design requires independent rows. Equality of row contents is a different question: two independent zero-filled rows can compare equal.

## A set of sets has membership semantics at both levels

This extension uses HashSet and LinkedHashSet, taught in the Sets group. The row construction/copy model above is complete without it. Return to this section after hash membership to apply that ownership model to a container used as a set member.

The final example builds two String sets with the same members in different encounter orders. They are equal as sets, so an outer set stores one distinct row membership. Outer Set uniqueness is not based on which row object was allocated or the order in which its inner values were inserted.

Using mutable sets as outer hash-set members is dangerous: the inner set's hashCode depends on its members. Editing a row after insertion can invalidate the outer membership relation. freezeDistinctRows copies each row into a private LinkedHashSet, wraps it and wraps the outer set. Strings/null are immutable values under this stated element model, so the membership used as a key remains stable. Changing the original input row later does not change the stored row.

This function preserves the source's supplied encounter order for diagnostics while defining equality by membership. An unordered source cannot recreate an ingestion history it never supplied.

<summary>Does matrix(2,0,0) have no rows?</summary>

It has two empty, independent row lists. Its total cell count is zero. matrix(0,3,0) has no rows at all. These are different shapes; retain row count separately when zero-column rectangles matter.

</details>

<details>
<summary>How would a nested unmodifiable view differ from the supplied snapshot?</summary>

Wrapping the original outer list alone leaves row mutation possible. Wrapping original rows as well blocks writes through those wrappers but can still observe other aliases. A snapshot first copies the required mutable levels, then exposes the desired unmodifiable boundary. The generic type syntax does none of that automatically.

</details>
