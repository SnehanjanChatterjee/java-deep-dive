## Determine the operation's type before computing

A **conversion** changes a value from one Java type to another, for example when assigning an int to a long variable. It is needed because a calculation's operands, a method's parameters and the variable receiving its result may use different types. Conversion can preserve a value, approximate it or discard information; the type names alone are not a proof of exactness.

Primitive numeric types have finite representations. The signed integral types store whole numbers with both signs; char stores a nonnegative UTF-16 unit. Floating-point types represent a range of binary approximations, together with special values. These are value formats, not measurements of the size of a containing object.

| Type | Value format | A boundary to remember |
| --- | --- | --- |
| byte | Signed 8-bit integer | −128 through 127 |
| short | Signed 16-bit integer | −32768 through 32767 |
| int | Signed 32-bit integer | −2147483648 through 2147483647 |
| long | Signed 64-bit integer | Larger whole-number range than int |
| char | Unsigned 16-bit unit | 0 through 65535; not a complete model of every character |
| float / double | 32-bit / 64-bit floating-point formats | Range and precision are separate limits |
| boolean | true or false | Does not convert to or from a number |

**Widening** is a permitted conversion to a broader type; **narrowing** usually requires an explicit cast such as `(byte) value`. **Numeric promotion** chooses the type used by an arithmetic operation. First determine that operation's type, then compute, then consider conversion into the receiving variable.

For example, `long total = 50_000 * 50_000;` multiplies two ints, overflows to -1794967296 and only then widens the result. Overflow means the mathematical result lies outside the operation's representable range. `50_000L * 50_000` uses long arithmetic and produces 2500000000. Math.multiplyExact instead reports an overflow when the requested result must fit its integer type.

## Separate widening, narrowing and numeric promotion

Byte, short and char normally promote to int for arithmetic. Binary numeric promotion then selects double, float, long or int from operand types. Boolean does not convert to a number. Char is an unsigned 16-bit UTF-16 unit; the other integral primitives are signed.

| Expression | Result | Explanation |
| --- | --- | --- |
| `byte b = 127;` | Accepted | Representable constant assignment |
| `int x = 127; byte b = x;` | Compile-time error | Nonconstant int does not implicitly narrow |
| `byte b = 1; b = b + 1;` | Compile-time error | Addition produces int |
| `byte b = 127; b += 1;` | -128 | Compound assignment includes narrowing |
| `double x = 5 / 2;` | 2.0 | Integer division precedes widening |
| `double x = 5 / 2.0;` | 2.5 | Floating-point promotion precedes division |

A widening conversion can lose precision: sufficiently large long values around 2^53 map to the same double. Range and precision are different properties. Floating arithmetic approximates many decimal fractions. Floating division by zero may produce infinity or NaN; integer division by zero throws. `Double.isNaN` tests NaN, which is unequal to itself under primitive equality. Primitive positive and negative zero compare equal; Double.equals distinguishes them and treats NaN according to its documented wrapper contract.

## Evaluate in a defined order

Precedence groups expressions; Java evaluates ordinary operands and arguments left to right. For `int n = 1; int total = n++ + ++n;`, the left yields 1 and stores 2; the right stores/yields 3; total becomes 4. Use separate statements in readable code. An exception in an earlier operand prevents later operand evaluation; prior side effects are not rolled back.

Integer division truncates toward zero, so `-7 / 3` is -2 and `-7 % 3` is -1. Math.floorMod is useful for a deliberately nonnegative remainder with a positive modulus. Minimum int divided by -1 overflows to minimum int; ordinary division does not detect that overflow. Shift distances use five bits for int and six for long: `1 << 32` is 1. `>>` propagates the sign bit; `>>>` inserts zeros.

## Boxing introduces a reference and a null policy

Integer, Long and other wrappers let primitive values participate in reference APIs. Boxing converts a primitive to a wrapper reference; unboxing obtains the primitive. `Integer value = null; int n = value;` throws NullPointerException during unboxing. The same can happen in `value == 0` or a conditional expression mixing wrapper and primitive alternatives.

Wrapper identity can depend on caching; use equals for values. A reference cast checks whether an existing object is compatible; `(Integer) anObject` does not parse a String into a number. `var` (Java 10+) infers a local's static type from its initializer; `var text = "hi"` remains String, and `var value = null` supplies no usable type.

## Explain precision and special values with actual results

<JavaExample file="NumericEdgesLesson.java" output={"66\nB\n16777216\nInfinity\n-Infinity\ntrue\ntrue\nfalse"} />

Char 'A' promotes to int 65 before addition, so the first result is 66. The explicit cast of that result to char gives B. The float literal 16777217F rounds to a representable float value before the int cast, so the later cast cannot recover the lost unit. Widening a type's range is different from preserving every significant bit.

Floating division by positive and negative zero yields infinities with different signs; zero divided by zero yields NaN, tested with isNaN. Primitive equality considers signed zeros equal, while Double.equals distinguishes them. For an interview prediction, name the operand types and the exact comparison operation before choosing an answer. Do not generalize integer divide-by-zero behavior to floating-point arithmetic.

Parsing text, boxing an existing number and casting an object reference are three different operations. Continue with <a href={lessonUrl('learn/language/wrappers-and-boxing/')}>wrapper values and null boundaries</a> for parseInt/valueOf, cross-wrapper equals and explicit null policies. None of those operations makes ordinary floating point suitable for every decimal monetary requirement; the decimal-arithmetic lesson later defines that separate domain.

## Practice: prevent the wrong kind of loss

Repair `long answer = 50_000 * 50_000` and explain why casting its result afterward is insufficient.

<details>
<summary>Answer</summary>

Use `long answer = 50_000L * 50_000;` or cast an operand before multiplication. `(long) (50_000 * 50_000)` widens the overflowed int, so the lost high bits cannot be recovered. For a required int result, use Math.multiplyExact and handle a value outside that domain. Apply this reasoning order: operand types → promotion → operation → assignment conversion.

</details>
