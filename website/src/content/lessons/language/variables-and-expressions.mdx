## Store a value, then compute another

A greeting uses fixed text. A calculation needs values that can be named, read and changed. A **variable** is a named place for a value; its **type** determines what kinds of values it can hold and which operations are legal. For a small whole-number quantity, use int. For text use String, and for a true/false answer use boolean.

In `int quantity = 3;`, int is the type, quantity is the name and 3 is the initial value. This is a **declaration with initialization**: it introduces the variable and gives it its first value. Later, `quantity = 4;` is an **assignment** to that existing variable. The equals sign performs assignment; `==` asks an equality question. A number or quoted text written directly in source is a **literal**.

An **expression** computes a value from literals, variables and operations. `quantity * unitPrice` multiplies two numbers; `nextTotal <= 20` asks whether one number is at most another and produces a boolean. Evaluating an expression happens at a particular point in execution. Storing its result does not create a permanently linked formula.

<JavaExample file="ExpressionBasics.java" output={"15\n20\ntrue"} />

`quantity * unitPrice` is an expression: it computes a value. The declaration of firstTotal stores 15. Changing quantity afterward does not recalculate firstTotal; nextTotal is a separate computation using 4. The comparison `nextTotal <= 20` produces a boolean, rather than another price.

## Read statements and scope

A statement is a unit of execution. Braces group statements into a block; main executes its statements in order. A local variable is usable from its declaration through the enclosing block's end. A variable declared inside an inner block is unavailable outside that block. Locals must be assigned before a read. Fields and array components instead receive default initialization, taught with objects and arrays.

`final` means this variable cannot be assigned again after initialization. It does not mean a calculation updates automatically or that a referenced object is immutable. Use names that express meaning, such as unitPrice; types begin the declaration, and semicolons end these statements. Java distinguishes upper and lower case.

## Build expressions intentionally

Arithmetic operators include `+`, `-`, `*`, `/` and `%`. For integer operands, `5 / 2` produces 2. Multiplication groups more tightly than addition, so `2 + 3 * 4` is 14; `(2 + 3) * 4` is 20. Parentheses make intended grouping visible. String `+` concatenates: `"total=" + nextTotal` produces text.

Comparisons `<`, `<=`, `>`, `>=`, `==` and `!=` produce booleans. Combine conditions with `&&` (both), `||` (either) and `!` (negation). `&&` skips its right operand when the left is false; `||` skips its right operand when the left is true. Boolean `&` and `|` evaluate both operands, unlike their short-circuit forms. Do not use a numeric zero as a boolean: Java has no implicit number-to-boolean conversion.

Java's primitives are byte, short, int, long, char, float, double and boolean. Choose int for these small counts. Long literals can use `L`; decimal floating-point literals normally have type double. A char literal uses single quotes, such as `'A'`; String literals use double quotes. Reference types such as String can also hold null, meaning no object. Numeric boundaries and conversions have a later dedicated chapter.

## Observe skipped operands and text concatenation

`++checks` adds one before yielding its value. This makes evaluation visible without a helper method:

<JavaExample file="ExpressionOrderLesson.java" output={"false\n0\nfalse\n1\nsum=12\nsum=3"} />

The first false left operand stops && before the increment, so checks stays zero. Boolean & evaluates the right operand even though its left operand already makes the answer false; checks becomes one. Both boolean results are false, but the side effects differ. Prefer simple conditions without mutation when that makes the code easier to read.

The + operator groups left to right. `"sum=" + 1` first creates text sum=1, then concatenates two, producing sum=12. Parentheses make `1 + 2` a numeric calculation before concatenation, producing sum=3. Precedence decides grouping; short-circuit rules decide whether a grouped operand is evaluated at all. A semicolon immediately after an if/loop condition would be an empty statement, not punctuation to insert between a condition and its intended body.

## Practice: distinguish a saved result from a formula

Predict `int x = 2; int y = x + 3; x = 10;` and then print y. Is it 5 or 13?

<details>
<summary>Answer</summary>

It is 5. `x + 3` was evaluated when y was initialized. To recompute, execute `y = x + 3;` after assigning 10. If y were final, that second assignment would be rejected. A later statement cannot use a local declared only inside a completed inner block.

</details>
