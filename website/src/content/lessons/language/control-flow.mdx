## Choose which statements run

So far, statements have run once from top to bottom. **Control flow** describes which statement runs next. A decision selects a path; a loop repeats a path. These let a program respond to its values instead of requiring a separately written statement for every possible input.

A **condition** is a boolean expression. An `if` statement runs its body—the controlled statement or brace block—only when its condition is true. An `else` supplies the alternative. In an else-if chain, the first true condition selects its body and skips the later alternatives. A score of 76 therefore reaches the pass branch in the example.

The same program then repeats additions and countdowns. Each pass through a loop body is an **iteration**. First follow the decision, then use the tables below to follow each loop's starting value, condition, body and update. A **dry run** means tracking those values by hand in execution order.

All statements are inside main, the entry method introduced in the first program. The sum loop visits 1, 2, 3 and 4, then prints 10. The next methods chapter packages repeated behavior into named operations; no additional method declaration is needed here.

The conditional operator chooses between two expression values: `score >= 50 ? "pass" : "retry"`. Only the selected alternative is evaluated. Use an if/else block when the branches are sequences of statements; use this compact form when choosing one value. Numeric alternatives can trigger conversions, developed in the numeric-boundaries chapter.

## Follow initialization, condition, body and update

In `for (int number = 1; number <= 4; number++)`, initialization happens once. Before every iteration, evaluate the condition. If true, execute the body and then the update. If false, continue after the loop. `number++` adds one after yielding its old value; here the yielded value is unused.

| Check | number | total before body | total after body |
| --- | --- | --- | --- |
| `1 <= 4` | 1 | 0 | 1 |
| `2 <= 4` | 2 | 1 | 3 |
| `3 <= 4` | 3 | 3 | 6 |
| `4 <= 4` | 4 | 6 | 10 |
| `5 <= 4` is false | 5 | 10 | No body execution |

Before each iteration, total is the sum of the integers already visited. This is a **loop invariant**, a statement that helps explain correctness. Each update makes progress toward termination. Replacing the upper limit 4 with 0 makes the first condition false and leaves total at zero. A loop can therefore execute no body at all.

## Choose a loop by its stopping rule

Use a for loop for a clear progression through a range. A while loop checks a condition before its body, so it can run zero times. The countdown prints 3, 2, 1 and stops when remaining reaches zero. Forgetting `remaining--` prevents progress.

A do-while checks after the body, so it executes at least once:

```java
int attempts = 0;
do {
    attempts++;
} while (attempts < 1);
// attempts is 1, even though there was no initial test
```

`break` exits the nearest loop or switch. `continue` skips the remainder of the current loop body; a for loop still performs its update before testing again. A nested loop has its own iterations: do not assume its inner break exits both loops. Labeled branching exists, but extracting a clear method is often easier to read.

## Dry-run nested break and continue targets

A **nested loop** is a loop inside another loop's body. The inner loop completes its own sequence for each outer iteration unless a branch leaves it. Naming the outer and inner values separately—row and column here—makes their two progressions visible.

<JavaExample file="LoopControlLesson.java" output={"1:1\n1:3\n2:1\nafter loops"} />

For row one, column one prints. Column two executes continue, which skips the print and performs the inner for update. Column three prints. Column four executes the unlabelled break, exiting only the inner loop; the outer loop proceeds to row two. That row prints column one and skips column two. At row two/column three, `break rows` leaves the labeled outer loop, so row three never begins. The statement after both loops still runs.

A label names a statement; it does not create another thread or make a jump to arbitrary source text. Use it sparingly when the exit target would otherwise be unclear. In a while loop, a continue before an update can prevent progress. When debugging a loop, trace the condition and next update on **every** path, not only the path that printed output.

<details>
<summary>Why is an accidental semicolon after for(...) particularly misleading?</summary>

It supplies an empty loop body. A following brace block is then a separate statement executed after that empty loop finishes. The source may compile while performing none of the intended repeated work. Braces and indentation help readers, but the language follows actual statements rather than indentation.

</details>

## Practice: repair a boundary and explain its effect

Change `number <= 4` to `number < 4`. What total is printed? How would you print only even numbers from 1 through 6?

<details>
<summary>Answers</summary>

It computes 1 + 2 + 3 = 6; 4 is excluded. For even numbers, a complete loop body is:

```java
for (int number = 1; number <= 6; number++) {
    if (number % 2 != 0) {
        continue;
    }
    System.out.println(number);
}
```

Output is 2, 4, 6 on separate lines. The continue skips printing odd numbers, but the for update still advances. A `while` variant must ensure every path advances, including a continue path. Increasing the sum loop's upper limit increases its number of body executions proportionally. The complexity lesson later formalizes this growth.

</details>
