## Name a calculation and return its result

A **method** is a named operation declared in a class. It packages a calculation or action so other code can request it without rewriting its statements. A method can receive input values, perform work and return one result. The code making the request is the **caller**; the method executing that request is the **callee**. One execution of a method is an **invocation** or call.

In `static int twice(final int value)`, int before twice is the result type, twice is the name and value is an input **parameter**. In `twice(7)`, seven is the **argument** supplied by the caller. On entry, the parameter receives that argument value. A `return` statement sends a result back to the call site and ends this invocation.

Follow twice first in the complete source. It illustrates a single input and result. The factorial method uses the same call/return mechanism repeatedly; its recursive progression is developed after ordinary return flow below. Static means these operations belong to the class and can be called here without first constructing an instance. Invalid-input guards use throw to stop the operation with a named failure; the exception lessons later explain that propagation in full.

<JavaExample file="MethodsRecursion.java" output={"14\n24"} />

Execution begins in main. Evaluating `twice(7)` enters twice with value equal to 7. `return Math.multiplyExact(value, 2)` supplies 14 to the caller and exits twice. Main stores that returned value in result, then prints it. The multiplication helper detects overflow; the failure mechanism is developed in exceptions. Ordinary `value * 2` can instead wrap at an int boundary.

A void method performs an action without returning a value; println is one. `return;` can exit a void method early. A non-void method must return a compatible value on every normal path. Returning is different from printing: a caller can store or combine a return value without displaying it.

## Each invocation has its own locals

Calling twice again creates another parameter variable with the new argument. Reassigning a primitive parameter cannot reassign the caller's local variable. Locals in one call are not shared with another call. A conceptual call frame records an invocation's parameters, locals and where execution will return; this is a reasoning model, not a promise about physical JVM allocation.

Static methods here belong to the class; instance methods later act on a particular object. A method signature distinguishes its name and parameter types. Begin with a unique descriptive name before introducing overload sets.

The caller invokes printPositive for -1, zero and one. On the first two calls, the guard returns from that helper without printing. It does not return from main or end main's loop. The third call prints one; after all calls, main prints its continuation. A return value belongs to a call, and the place execution resumes belongs to its caller.

Parameter names document roles but do not distinguish overload signatures. A non-void method whose if branches can both finish without a return is rejected; printing a value in a branch does not satisfy a return obligation. A recursive method also needs both a reachable stopping case and progress toward it. Merely adding `if (n == 0)` cannot save a recursive branch that calls itself again with unchanged n.

## Make recursive progress and stop

**Recursion** occurs when a method calls itself, directly or through other calls. It is useful when a problem can be reduced to a smaller problem of the same shape. It still uses ordinary invocation rules: each call has its own parameters and must eventually return.

The **factorial** of a positive whole number is the product from that number down to one: factorial(3) is 3 × 2 × 1, or six. Define factorial(0) as one. This gives the recursive rule `factorial(n) = n * factorial(n-1)` for positive n. The **base case** handles zero without another call; the recursive branch makes progress by reducing n.

| Invocation | Waits for | Returns |
| --- | --- | --- |
| factorial(3) | 3 × factorial(2) | 6 |
| factorial(2) | 2 × factorial(1) | 2 |
| factorial(1) | 1 × factorial(0) | 1 |
| factorial(0) | No further call | 1 |

The multiplication happens as calls return, from the base case outward. Validation rejects negatives, which would otherwise keep decreasing, and values above 20, whose factorial cannot fit a long. Valid n takes a number of multiplications and nested invocations proportional to n, written O(n). This notation describes growth as input increases; the later algorithm-analysis lesson develops it in detail.

## Practice: write the iterative factorial

Implement the same 0..20 contract using a loop. Explain why the initial product is 1 rather than zero.

<details>
<summary>Solution</summary>

```java
static long factorialIterative(final int number) {
    if (number < 0 || number > 20) {
        throw new IllegalArgumentException("number must be between 0 and 20");
    }
    long product = 1L;
    for (int factor = 2; factor <= number; factor++) {
        product *= factor;
    }
    return product;
}
```

One is multiplication's identity and gives the required zero-factorial result when the loop executes zero times. Starting at zero would make every result zero. The iterative version takes O(n) multiplications and constant auxiliary storage. Arbitrarily deep recursion can cause StackOverflowError; Java does not guarantee tail-call elimination. Prefer the form whose progress and space use you can explain.

</details>

## Solved coding exercise: detect a prime without overflowing the bound

A **prime number** is a whole number at least two whose only positive divisors are one and itself. To classify a number, try potential divisors and stop as soon as one divides evenly. This exercise combines a method's boolean result, an early return and a loop with a justified stopping condition.

<JavaExample file="PrimeTrialDivisionLesson.java" output={"false\ntrue\nfalse\ntrue"} />

IsPrime first rejects values below two; one is not prime. For each divisor from two, it returns false if remainder is zero. A composite number has a factor no larger than its square root, so testing all smaller possible divisors is sufficient. `divisor <= number / divisor` expresses that boundary for a positive number without evaluating an overflowing int square. Divisor is never zero.

For 49, divisors two through six leave a nonzero remainder; seven divides exactly and returns false. For 97, divisors two through nine fail and the next bound fails, so true is returned. The invariant is that no previously tested divisor divides number. Worst-case work is O(sqrt(n)) trial divisions with constant working storage. The test includes Integer.MAX_VALUE to exercise the bound that a naive `divisor * divisor <= number` can break. This is a teaching primality test for int input, not a cryptographic primality algorithm.
