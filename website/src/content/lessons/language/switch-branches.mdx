## Group discrete alternatives

Sometimes a decision asks which one of several named values an input has, rather than whether it lies in a range. A **switch** expresses that selection once. Its **selector** is the expression being examined. A **case label** names a value to match, and **default** supplies the path when no named case matches.

For numbered days, the selector is day: one through five mean weekday, six and seven mean weekend, and other numbers are outside the chosen domain. An if/else chain could express the same decision. Switch groups the alternatives around the one value being selected; it does not repeatedly ask unrelated boolean questions.

Day is seven, so execution enters the case-seven group, assigns weekend and breaks out of the switch. The print after the switch still executes. The final local kind is assigned on every path, including default, so its later read is valid. Grouped labels perform no action by themselves: cases six and seven reach the same assignment.

## Explain colon-label fallthrough

With colon labels, execution continues into following statements and labels unless something transfers control. A return exits the method. A break exits the switch, allowing statements after the switch to run. Merely reaching another case label does not stop execution. This makes intentional grouping possible, but can also accidentally execute a later group's work.

This continuation is called **fallthrough**. The selector chooses the entry point, not a separate sealed box around each colon-labeled group. Trace both where execution enters and which statement ends that path. Break is sufficient for the statement-only program here; the method lesson explains return before the optional helper comparison below.

For a variable assigned inside a switch, definite assignment must cover every path before the variable is read. Do not add a silent default value simply to conceal an unhandled domain case. Classic selectors have restrictions on accepted types; the pattern-switch chapter later extends the model to type alternatives and explicit null handling. A null boxed or String selector in a classic switch throws rather than selecting default.

## Use a value expression when every path computes a value

Java 14+ finalizes switch expressions and arrow rules. In a source file targeting that release or later, the same choice can return a value directly:

```java
final String kind = switch (day) {
    case 1, 2, 3, 4, 5 -> "weekday";
    case 6, 7 -> "weekend";
    default -> throw new IllegalArgumentException("invalid day");
};
```

Arrow rules do not fall through. A block arm can use yield to provide the switch expression's value; yield is different from returning from the enclosing method. A switch expression must produce a value or complete abruptly on every required path. The classic runnable example remains usable on Java 8.

Each selected group returns text to main. Return leaves the helper, whereas break in the first program leaves only the switch. This optional comparison uses the same selection concept with a different continuation point; it is not required to run the statement-only introduction.

Classic Java 8 switch accepts byte, short, char, int, their corresponding wrappers, String and enums. It does not accept long, floating-point or boolean selectors. Classic integral/String case labels must be suitable compile-time constants; duplicate labels are rejected. These restrictions describe the classic form here, while later pattern matching and version-specific extensions have their own rules.

## Practice: choose break or return

A switch appears in a method that must print a footer after choosing a message. Should each case return immediately?

<details>
<summary>Answer</summary>

Return would skip the footer by exiting the method. Assign a message and break from each ordinary colon group, then print the message/footer after the switch. On Java 14+, an expression assigned to a local often makes this structure clearer. If exiting the entire method is the intended behavior, return is appropriate. State the desired continuation point before selecting a branching keyword.

</details>
