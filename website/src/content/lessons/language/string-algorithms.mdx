## Solve the declared text problem

Reversal and first-unique search need an explicit text unit. These algorithms operate on Unicode **code points**, preserving supplementary surrogate pairs. They do not promise grapheme-cluster editing, normalization or case-insensitive equivalence. The ordered map preserves first appearance so a second traversal can select the first unique point.

## Reverse from an exclusive end offset

ReverseCodePoints starts at input.length, obtains codePointBefore(end), appends the full point and subtracts Character.charCount(point). The invariant is that the builder contains the reversed suffix already visited, with no valid surrogate pair split. When end reaches zero, every code point has been appended. Null is rejected; empty text returns empty text. Time is O(n) with O(n) output storage for n UTF-16 units.

## Count without assuming a map default value

FirstUnique traverses code points from left to right. Get returns an Integer count or null when absent. Put stores one for an absent point or previous + 1 for a present point. The explicit null test protects unboxing; a missing mapping is not automatically the number zero. LinkedHashMap retains the first insertion order while later count replacements leave that order intact.

The second traversal reads entries in first-appearance order and returns the first key whose count is one. For swiss, the final counts are s=3, w=1, i=1, and w is selected before i. Expected time is O(n), with O(k) map storage for k distinct points under ordinary hashing assumptions.

## Return absence without a misleading character sentinel

OptionalInt represents either one int or no int. OptionalInt.of(point) wraps a found code point; OptionalInt.empty() reports absence. IsPresent asks whether it contains a value; getAsInt requires a present value and otherwise throws. This small result API is all the example needs; the functional module later teaches Optional composition.

In main, swiss has a unique w, so getAsInt is valid. Aabb has none, so isPresent prints false. Empty input also has no unique point. Returning -1 instead could be a documented code-point sentinel, but a result type communicates absence explicitly and prevents accidental treatment as an ordinary code point.

## Practice: preserve grapheme clusters?

Will reversing code points keep a combining accent attached to its base letter? Why not use a HashMap and return its first entry with count one?

<details>
<summary>Answers</summary>

No: grapheme clusters may contain several code points, and reversing their order changes that cluster. A grapheme-aware editor needs segmentation under its required text rules. HashMap has no first-appearance iteration guarantee, so its first unique entry need not be the first unique point in the input. Keep LinkedHashMap or perform a second traversal of the original code points against the counts.

</details>

## Dry-run supplementary reversal and ordered counting

For A😀B, the reverse loop begins at exclusive offset four. CodePointBefore(4) reads B and moves end to three. The next read obtains the full emoji from the surrogate pair and moves end to one. The final read obtains A and moves end to zero. Appending a point, rather than casting it to char, preserves its two-unit encoding. Empty input enters no iteration; null fails before length is read.

For swiss, the counting states are s→1, then w→1, then i→1, then s→2 and s→3. Replacing an existing s count leaves s first in encounter order. The second traversal skips s because three is not one, then returns w. It returns a **code point**, not the original UTF-16 index; an API requiring a source offset would need to retain or find that offset explicitly.

## Solved exercise: remove trailing whitespace only

The same canonical source contains stripTrailingWhitespace. It starts at the exclusive end, reads the preceding full code point, and moves left only while Character.isWhitespace accepts that point. It returns substring(0, end), preserving all leading text and the first non-whitespace suffix boundary. For `"  Ada \t"` the result is `"  Ada"`; empty and all-whitespace inputs return empty text.

This policy differs from Java 8 trim, which uses its documented small-code-unit boundary. Character.isWhitespace includes an em space but excludes some nonbreaking spaces, so the test intentionally keeps U+00A0. A product requirement to remove those too must change the predicate. Scanning a suffix takes O(k) inspected code points; constructing the returned prefix can require O(n) storage/work, so do not label the whole operation O(k) regardless of output size.

<details>
<summary>Would recursive reverse(input.substring(0, n-1)) be an equivalent solution?</summary>

Not with a char-at-a-time boundary: it can split surrogate pairs. It also creates nested invocations and, on typical current substring implementations, repeatedly copies prefixes, producing quadratic total copied work. The iterative code-point solution uses one builder and states its grapheme limitation explicitly. Neither method becomes a normalization algorithm merely because it handles supplementary points.

</details>
