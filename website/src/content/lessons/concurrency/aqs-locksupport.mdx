## Build a gate that stays open after its first release

A **synchronizer** is an object coordinating permission or progress through shared state and waiting. **AbstractQueuedSynchronizer**, abbreviated **AQS**, is a library framework for building such objects. A subclass defines what its integer state means and which transitions permit progress; the framework supplies the contended waiting/retry machinery around that policy.

Study it with an **open-once signal**. State zero means closed and state one means permanently open. An await caller may pass only at one; opening allows all current and future awaiters to pass. Open is **idempotent**: repeating it leaves the same open state rather than creating additional consumed permits.

Here **acquisition** means asking whether the caller may proceed, and **release** changes state so waiters may become eligible. This shared event has no exclusive owner and does not decrement state as each waiter passes. That differs from a reentrant lock's ownership count and a semaphore's available-permit count.

The mental model has two parts: a persistent gate predicate and a queue of callers waiting to retry it. This queue contains waiting threads, rather than the work items in an executor queue. **Parking** is the runtime waiting facility used to suspend a thread instead of making it spin; LockSupport exposes the low-level park/unpark operations studied after the complete gate.

Read the public await/open wrapper first, then the nested Sync policy methods. This is an implementation exercise explaining how familiar blocking utilities can be built on a framework, rather than a reason to replace an existing CountDownLatch in ordinary application code.

The wrapper exposes interruptible await, bounded await and idempotent open. A private nested Sync extends AbstractQueuedSynchronizer. Callers cannot reinterpret its raw integer state. Await delegates to shared acquisition; open delegates to shared release.

TryAcquireShared returns negative while state is zero and positive once state is one. It never decrements state, because passing one waiter must not close the gate for the next. TryReleaseShared CAS-transitions zero to one and returns true only for that first transition, allowing the framework to signal eligible waiters. Later calls return false while future acquisition still succeeds from the open state.

## State policy and waiting machinery are different responsibilities

AQS supplies contended acquisition, wait queues, cancellation and wakeup mechanics around the subclass policy. It does not decide what the integer means, make every synchronizer fair, or grant a consumed resource on every success. Reentrant counts, shared permits and this open-once event need different transitions.

An exclusive mutex permits one owner; a shared event can release multiple waiters. An internal FIFO-style queue does not itself guarantee fair acquisition: a fast path can barge unless the subclass policy prevents it. Owner tracking, reentrancy, invalid-release behavior and fairness must be supplied deliberately for a lock-like wrapper.

## LockSupport permits are not a counting semaphore

LockSupport associates at most one available permit with a thread. Park can consume one immediately. Unpark makes a permit available if absent, so an unpark before a later park on a started thread can prevent blocking. Multiple unparks do not accumulate arbitrary credits; unparking before start is not a reliable startup/publication protocol.

Park can also return for interruption or spuriously; timed forms add expiry. It does not tell the caller which reason occurred and does not clear interruption like an InterruptedException-reporting wait. Recheck the predicate and honor cancellation. Parking repeatedly with interrupted status still set can create a busy failure loop.

Park releases neither intrinsic monitors nor explicit locks already held. Retaining a lock needed by the condition's producer can prevent progress. The blocker argument aids diagnosis; it is not a monitor park acquires/releases. Unpark alone is not the publication proof for arbitrary payload fields.

## Dry-run a park permit and the persistent predicate

For an already-started target, two unparks before its next park leave **at most one** permit. One park can consume it and return. A later park has no second stored credit from those two calls; it may wait, return for interruption or return spuriously. Never turn this illustration into a test asserting that a particular park must block.

The persistent application predicate is therefore essential. For OneShotSignal, state one remains open even after a waiter returns. A second waiter can pass because it rereads open state, not because the first unpark created an unlimited number of wakeup credits. AQS's acquire/release machinery connects that policy with eligible waiters.

| Mechanism | What remains after an early signal? |
| --- | --- |
| Object.notify with no waiters | No notification credit |
| LockSupport.unpark on a started thread | At most one thread-associated park permit |
| Semaphore.release | An additional permit under its counting protocol |
| OneShotSignal.open | Persistent open state for current and future awaiters |

Park also retains locks the caller already owns. If the producer needs such a retained lock to make the predicate true, parking can preserve a closed dependency cycle. Higher-level condition waits have a different release/reacquire protocol. Do not substitute park mechanically for Object.wait or Condition.await. ## Await, timeout, publication and conditions

The source writes a plain array element before opening. A successful shared acquire after release publishes the preceding write, so the waiter reads 42. Join still owns worker cleanup, but the payload proof follows the synchronizer protocol. The closed event's zero-time wait returns false; open can succeed without waiting. Timeout does not open the event or cancel its producer.

Timed await validates duration/unit and delegates to the matching AQS method. The inherited serializable helper declares serialVersionUID; the wrapper does not promise a published serialization protocol.

Conditions apply only to suitable exclusive synchronizers that can release and later restore their ownership state. A condition wait queue differs from the main acquisition queue. This ownerless event deliberately supplies no condition API. OpenJDK node fields/signalling helpers change across releases; study responsibilities before memorizing private helper names.
