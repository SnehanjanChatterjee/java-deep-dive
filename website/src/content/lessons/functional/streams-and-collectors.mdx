## Describe a data transformation

A loop can select long words and normalize them. A stream pipeline expresses the same source, selection and transformation as separate stages. The stream is not a container; it describes how to obtain a result from a source. The source collection can remain unchanged.

<span id="worked-example" aria-hidden="true"></span>
## Translate a loop into a pipeline

<JavaExample file="StreamFoundationsLab.java" output={"[JAVA, JVM]\n[JAVA, JVM]\n[A, B, C]\n4"} />

The loop visits java, a, jvm; rejects a because its length is below three; transforms the survivors; and appends JAVA/JVM to a result. The pipeline uses the same steps: words.stream supplies String elements, filter keeps matching Strings, map transforms each String, and collect materializes a List. The intermediate element type remains String here; mapping String::length instead would produce Stream&lt;Integer&gt;.

Intermediate operations return another stream and are generally lazy. The terminal operation requests a result and triggers evaluation. Creating the pipeline alone does not promise its callbacks have run. A stream instance is used once; obtain a new stream from the source for another result rather than reusing a consumed stage.

## Obtain a source deliberately

Use collection.stream(), Arrays.stream(array), Stream.of(values), or a source-specific API such as Files.lines. Map has no direct stream method; stream its entrySet, keySet or values depending on the required element shape. Stream.iterate/generate can produce unbounded sources, so later operations must establish termination.

Resource-backed sources still need closing. A stream from an ordinary collection usually owns no external resource; Files.lines and Files.walk do. A terminal operation does not replace try-with-resources. Returning a stream after closing its resource creates an invalid lifetime.

## Follow demand one element at a time

The final program expression filters even numbers, squares them and finds the first result. It can reject 1, accept 2, produce 4 and stop. It need not create a complete filtered list or evaluate 3 and 4.

This model illustrates a legal sequential traversal of [1,2,3,4], filter-even, square and findFirst. It is a teaching model rather than a JVM execution transcript. The Stream contract permits optimizations when callbacks cannot affect the required result; do not place mandatory auditing or writes in peek/map and depend on every invocation occurring.

## Change one-to-one mapping into flattening

A Stream of lists contains list objects as its elements. map(List::stream) produces a stream whose elements are streams. flatMap(List::stream) traverses those inner results and emits their elements into one outer stream. In the example, [A,B] and [C] become A,B,C. A flatMap mapper may emit zero, one or many results.

The later word-frequency program lowercases each line with Locale.ROOT, splits it into words and flattens them. Only then does grouping count the words. Keep those shapes separate when reasoning about nested pipelines. mapMulti on Java 16+ can emit zero/many outputs through a supplied consumer without an intermediate-stream shape; the consumer must not be retained beyond its invocation contract.

## Predict state and termination

| Operation category | Examples | What the learner must account for |
| --- | --- | --- |
| Stateless intermediate | filter, map, flatMap | Per-element transformation |
| Stateful intermediate | sorted, distinct | Buffering/state and source size |
| Short-circuiting intermediate | limit; takeWhile — 9+ | Encounter order and termination |
| Terminal result | collect, count, toArray, reduce | Consumes the pipeline |
| Short-circuiting terminal | findFirst, anyMatch, findAny | May consume only part of a source |

sorted before limit on an infinite source need not terminate: sorting cannot determine its first value while unknown earlier values might remain. limit before sorted bounds the input but computes a different operation.

<span id="common-mistakes" aria-hidden="true"></span>
## Keep the source and evaluation contract intact

Do not mutate the source while traversing it or reuse a consumed stream. Encounter order comes from the source and operations: List has one, HashSet does not promise one. unordered relaxes an order requirement; it does not shuffle. Stream.toList on Java 16+ returns an unmodifiable list and can contain nulls; Collectors.toList makes no general implementation/mutability promise; List.of rejects nulls.

<span id="exercises-and-interview-questions" aria-hidden="true"></span>
## Worked questions

**Why might count skip peek?** If exact size is known and the skipped stage cannot change the answer, the implementation can omit traversal. A source's Spliterator exposes properties such as ORDERED, SIZED, SUBSIZED, DISTINCT, SORTED, NONNULL, IMMUTABLE and CONCURRENT. Mapping can invalidate sorted/distinct knowledge; filtering generally loses exact size. These are actual properties, not decorations to invent.

**What changes with a primitive stream?** mapToInt produces IntStream with primitive arithmetic/terminal methods. It avoids a boxed result contract, but int sum can still overflow. The reduction chapter separates arithmetic policy from pipeline spelling.
